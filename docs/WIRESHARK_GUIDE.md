# Network Security Analysis: Wireshark Packet Capture Guide

**Course:** Cryptography and Network Security — 26ECSC403  
**Viva Exhibit:** Transport Layer Security (HTTP vs. HTTPS Capture Analysis)

---

## 1. Objective

To provide undeniable experimental evidence of why Transport Layer Security (TLS/HTTPS) is mandatory for healthcare systems. We capture and analyze network packets during a user login under two conditions:
1. **Unencrypted HTTP:** Credentials and session cookies are transmitted in cleartext and readable by any network sniffer.
2. **Encrypted HTTPS (TLS):** The entire transaction is protected by modern asymmetric and symmetric cryptography, rendering packets completely opaque to eavesdroppers.

---

## 2. Step-by-Step Wireshark Capture Instructions

### Step 1: Start Wireshark
1. Launch **Wireshark** on Windows.
2. Under capture interfaces, select **Adapter for loopback traffic capture** (Npcap Loopback Adapter).
3. Set the capture filter in the top bar to:
   ```
   tcp.port == 5000
   ```

---

### Step 2: Capture Unencrypted HTTP Login
1. In your terminal, start the server in plain HTTP mode:
   ```powershell
   python run.py --port 5000
   ```
2. Open your web browser and navigate to:
   ```
   http://127.0.0.1:5000/login
   ```
3. Enter credentials:
   - **Username:** `doctor_alice`
   - **Password:** `DocSecurePass#2026`
4. Click **Sign In**.
5. Stop the Wireshark capture.

#### Packet Analysis (HTTP):
- In Wireshark, type `http.request.method == "POST"` in the display filter.
- Right-click the captured `POST /login` packet &rarr; select **Follow** &rarr; **TCP Stream**.
- **Result:** You will see the raw, unencrypted HTTP payload:
  ```http
  POST /login HTTP/1.1
  Host: 127.0.0.1:5000
  User-Agent: Mozilla/5.0 ...
  Content-Type: application/x-www-form-urlencoded
  Cookie: session=eyJ...
  
  csrf_token=...&username=doctor_alice&password=DocSecurePass%232026
  ```
- **Vulnerability Highlight:** The password `DocSecurePass#2026` and session cookie are transmitted in plaintext across the local network segment. Anyone running Wireshark or ARP poisoning on the same LAN can steal the credentials immediately.

---

### Step 3: Capture Encrypted HTTPS Login
1. In your terminal, start the server with TLS enabled:
   ```powershell
   python run.py --https --port 5000
   ```
2. Start a fresh Wireshark capture on the **Npcap Loopback Adapter**.
3. Open your browser and navigate to:
   ```
   https://127.0.0.1:5000/login
   ```
   *(Accept the local self-signed certificate security prompt in your browser).*
4. Enter credentials:
   - **Username:** `doctor_alice`
   - **Password:** `DocSecurePass#2026`
5. Click **Sign In**.
6. Stop the Wireshark capture.

#### Packet Analysis (HTTPS):
- In Wireshark, set the display filter to:
  ```
  tls
  ```
- You will observe the standard TLS handshake sequence:
  1. `Client Hello` — Supported cipher suites (e.g., `TLS_AES_256_GCM_SHA384`, `TLS_CHACHA20_POLY1305_SHA256`).
  2. `Server Hello` — Selected cipher suite and server key exchange parameters.
  3. `Certificate` — The local X.509 certificate generated by `certs/generate_certs.py`.
  4. `Application Data` packets — All subsequent HTTP POST requests and server responses.
- Right-click any `Application Data` packet &rarr; select **Follow** &rarr; **TCP Stream**.
- **Result:** The data payload consists entirely of high-entropy pseudo-random bytes:
  ```
  .....4..{.....$.0.U...Y.J...z...e.>.^...4.*..%.O..e...
  ```
- **Security Guarantee:** Neither the request URL path, the credentials (`username`, `password`), the headers, nor the patient diagnosis can be deciphered by an attacker without the server's private key.

## 3. Comparison Summary Table

| Metric | HTTP (Port 5000) | HTTPS / TLS 1.3 (Port 5000) |
|---|---|---|
| **Protocol Type** | Plaintext TCP / HTTP 1.1 | Encrypted TLS record protocol |
| **Credential Visibility** | Plaintext ASCII (`DocSecurePass#2026`) | Encrypted ciphertext blocks |
| **Session Cookie Exposure** | Plaintext in `Cookie` header | Fully encrypted inside TLS payload |
| **Man-in-the-Middle Risk** | High (trivial credential theft) | Mitigated by cryptographic channel encryption |
| **Integrity Protection** | None (packets can be forged) | HMAC / AEAD MAC on every TLS packet |
